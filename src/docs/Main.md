ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ: ГЛАВНЫЙ ДАШБОРД (Main) И ХУК ФИЛЬТРАЦИИ

Документация описывает архитектуру центральной контентной зоны приложения (компонент Main.jsx), которая полностью разгружена от вычислительной бизнес-логики с помощью двух кастомных хуков. Архитектура построена на принципах DRY и KISS.

1. Компонент Main.jsx (Диспетчер)

Роль в архитектуре: Чистый управляющий компонент-контейнер, выполняющий роль главного высокоуровневого координатора страницы. Компонент полностью освобожден от вычислительной бизнес-логики, регулярных выражений, дебаунс-таймеров и асинхронных эффектов запросов.
Зоны ответственности:
• Организация структуры дашборда: Задает глобальную двухблочную геометрию страницы и взаимное расположение основных контентных зон.
• Подключение архитектурных слоев: Интегрирует два независимых кастомных хука — один для управления логикой отображения интерфейса (мобильная шторка), второй — для работы со сквозными потоками данных.
• Распределение потоков данных (Диспетчеризация): Декларативно распределяет готовые массивы вопросов, параметры пагинации, поисковые запросы и функции-сеттеры фильтрации между дочерними модулями.
• Связывание независимых компонентов: Выступает «мостом» для обмена сигналами между изолированными соседними элементами, которые физически не могут общаться друг с другом напрямую.

2. Механика взаимодействия и анимации сайдбара Parameters

Поскольку компоненты Questions (где находится кнопка открытия) и Parameters (где находится кнопка закрытия) являются соседними и лежат внутри одного родительского файла Main.jsx, для обмена данными применяется паттерн поднятия состояния (Lifting State Up). Архитектурный стейт управления находится в родителе, который передает функцию открытия в один компонент, а функцию закрытия и статус видимости — во второй через механизмы пропсов.

🔄 Пошаговая работа системы на практике:

1. Инициация процесса: Пользователь нажимает на кнопку с иконкой фильтра в заголовке списка вопросов (Questions). Срабатывает проброшенная сверху функция onOpenFilters().
2. Переключение триггера: Родительский контейнер Main.jsx перехватывает этот сигнал и переводит свое внутреннее состояние видимости сайдбара в значение true.
3. Реакция и трансформация верстки: Компонент параметров моментально реагирует на изменение входящего пропса isFiltersVisible. На основе этого флага срабатывает условие динамического добавления классов. К основному контейнеру подмешивается класс активности .display, который снимает CSS-ограничения, запускает плавающий режим позиционирования и сдвигает координаты панели.
4. Мягкое демпфирование: Одновременно с появлением панели на экране рендерится фоновый оверлей, который плавно затемняет остальной интерфейс сайта и берет на себя роль ловушки кликов для закрытия меню по пустой области.
5. Деактивация и закрытие: Пользователь нажимает на кнопку-крестик внутри панели параметров или кликает по затемненному фону. Срабатывает функция onCloseFilters(). Родитель возвращает стейт в значение false, класс активности .display удаляется, и сайдбар плавно уезжает за границы экрана.

3. Функциональные изменения и доработки интерфейса

В ходе оптимизации адаптивного слоя дашборда были внедрены профессиональные интерфейсные решения, улучшающие мобильный и десктопный UX приложения:
1. Ликвидация резких прыжков верстки: Компонент полностью переведен с мгновенного переключения свойства display на плавную анимацию. Поскольку гибкая флекс-модель сайдбара теперь активна в мобильном режиме всегда, браузер корректно считывает изменения числовых координат трансформации (transform: translateX) и плавного изменения прозрачности (opacity). Сайдбар за 300 миллисекунд элегантно выезжает справа налево.
2. Безопасность скрытого состояния: Использование свойства visibility: hidden в закрытом состоянии шторки гарантирует, что сайдбар, физически находящийся за правым краем экрана, полностью исключается из дерева взаимодействия браузера. Он становится «невидимым» для курсора мыши, случайных кликов и системного фокуса.
3. Адаптивный расчет высоты: Жёсткая фиксация высоты панели заменена на автоматическую подстройку под объем контента. Сайдбар аккуратно сжимается на странице вопроса, где параметров мало, и растягивается на главной странице, предотвращая появление пустых визуальных зон. При этом свойство максимальной высоты (max-height) со встроенным независимым скроллом гарантирует доступность всех элементов при переполнении.
4. Умная блокировка прокрутки (Scroll Lock): Специализированный асинхронный эффект отслеживает статус открытия панели фильтров. При активации сайдбара он намертво блокирует прокрутку фоновой страницы списка вопросов (Questions), предотвращая хаотичное смещение контента под оверлеем при скролле на мобильных устройствах.
5. Компенсация сдвига окон: В момент блокировки фонового скролла системная полоса прокрутки браузера исчезает, что на десктопах обычно вызывает резкий рывок всей верстки сайта вправо на 15–17 пикселей. Разработанный алгоритм динамически вычисляет точную ширину скроллбара конкретного пользователя и компенсирует его исчезновение правым отступом (padding-right) для тега body. Верстка сайта и фиксированной шапки хедера остается монолитной пиксель-в-пиксель.

Компонент формирует двухблочную структуру дашборда, используя паттерн спреда пропсов ({...filterState}) 

📐 Кастомный хук useQuestionsFilter.js (Бизнес-логика)

Роль в архитектуре: Изолированное ядро управления состоянием данных всей главной страницы. Кастомный хук инкапсулирует в себе полный цикл асинхронного взаимодействия с API, дебаунс поисковой строки, сборщиков уникальных тегов и глубокую клиентскую фильтрацию.

⚙️ Инкапсулированные процессы и стейты:

1. Серверная пагинация (questions, currentPage, totalPages):
	• Следит за порционной загрузкой данных по 10 штук с сервера через API-запрос ?page=${currentPage}&title=${...}.
	• При получении ответа от бэкенда динамически высчитывает общее количество доступных серверных страниц (Math.ceil(total / limit)), передавая его в стейт totalPages.
2. Поисковый Debounce (searchQuery и debouncedSearchQuery):
	• Использует useRef(null) для управления таймером setTimeout. При вводе каждой буквы предыдущий таймер сбрасывается. Пауза в 400 мс перезаписывает строку в debouncedSearchQuery, что триггерит новый безопасный запрос к API без перегрузки бэкенда холостыми запросами.
3. Санитар данных (decodeHtmlString):
	• Встроенный хелпер пробегается регулярным выражением по пришедшему массиву вопросов, срезает технические кавычки бэкенда по краям строк (" или "$), а через виртуальный тег textarea «расшифровывает» текстовые мнемоники спецсимволов (&lt; → <, &quot; → ").
4. Сборщики уникальных тегов (Map):
	• На основе пришедшей порции вопросов questions динамически через структуры new Map() собирает уникальные массивы uniqueSpecs и uniqueSkills, отсекая дубликаты ID. Они пробрасываются в компонент параметров под именами specializations и skills.
5. Глубокая клиентская фильтрация (filteredQuestions):
	• Поверх загруженных 10 карточек накладывает синхронный метод .filter(). Вопросы проходят валидацию по четырем осям: пересечение по массивам выбранных специализаций, навыков, диапазонов сложности (complexity) и точечного рейтинга (rate).

🛡️ Паттерн Функциональных Декораторов (Решение проблем сброса пагинации)

Для предотвращения критической ошибки линтера Calling setState synchronously within an effect can trigger cascading renders и полной разблокировки пагинации, в хуке применен паттерн функций-декораторов (createFilterSetter):
• Из хука наружу в левую колонку уходит абсолютно чистая, оригинальная функция setCurrentPage. Это позволяет компоненту <Pagination /> безопасно выполнять колбэки вида setCurrentPage(prev => Math.max(prev - 1, 1)). React берет актуальный номер страницы из памяти, и переход по всем 170 страницам базы работает без зависаний.
• Функции изменения кнопок-фильтров в сайдбаре (для компонента Parameters) оборачиваются специальным хелпером. Сброс страницы на первую (setCurrentPage(1)) выполняется строго в момент физического клика пользователя по кнопке тега, а не во время внутренних перерендеров эффектов. Это гарантирует точный сброс на 1-ю страницу при поиске нового навыка и полностью ликвидирует каскадные циклы рендеринга.
