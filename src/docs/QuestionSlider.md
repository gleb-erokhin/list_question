Перенос всей логики переключения, хуков роутера (useNavigate, useLocation) и расчета соседей (prevId/nextId) внутрь QuestionSlider.jsx — это классический паттерн инкапсуляции. Теперь компонент стал полностью автономным «умным» слайдером, а родительский QuestionPage максимально разгрузился, так как ему больше не нужно знать ничего про индексы, массивы соседей и навигационные переходы — он просто передает текущий id через пропсы.

Компонент QuestionSlider.jsx (Умный слайдер)
Роль в архитектуре: Автономный функциональный компонент навигации (Smart UI Component). Полностью инкапсулирует в себе логику перемещения по базе вопросов, чтение контекста роутера и расчет соседей текущего элемента.

📥 Входные параметры (Props):
• id (String/Number, обязательный): Идентификатор текущего активного вопроса, полученный от родительского компонента QuestionPage.

⚙️ Внутренняя логика и расчеты:
1. Считывание контекста страницы: Через хук useLocation компонент заглядывает в скрытое состояние роутера (location.state) и извлекает оттуда массив allIdsOnPage (ID всех вопросов, отрендеренных на главной странице, Массив реальных ID вопросов, переданный в скрытом состоянии роутера с главной страницы. Используется для построения "бесконечной" навигации по соседям без жесткой привязки к математическому шагу +1.). Если состояние пустое, инициализирует пустой массив.
2. Динамический расчет индексов: При каждом рендере (и при изменении пропса id) код безопасно приводит типы к строкам и находит текущую позицию элемента:
	• currentIndex: Порядковый номер текущего вопроса в массиве allIdsOnPage.
	• prevId: ID левого соседа. Равен элементу currentIndex - 1 (если мы не на самом первом элементе).
	• nextId: ID правого соседа. Равен элементу currentIndex + 1 (если мы не уперлись в конец массива).
3. Автономные переходы: Хук useNavigate осуществляет программный переход на /questions/:prevId или /questions/:nextId. Функции handlePrevQuestion и handleNextQuestion в обязательном порядке пробрасывают весь массив allIdsOnPage в параметр state следующей страницы, обеспечивая непрерывность скользящей навигации.

🛡️ Безопасность переходов (PROD-блокировка):
Если prevId или nextId возвращают null (пользователь находится на краях доступного списка, например на 1-м или 10-м элементе), кнопки автоматически получают атрибут disabled. На уровне CSS-модуля включаются жесткие ограничения:

.btnNav:disabled {
  pointer-events: none; /* Полная блокировка кликов на уровне браузера */
  cursor: not-allowed;  /* Системный курсор запрета */
  opacity: 0.5;
}
