Хук выполняет роль изолированного ядра управления данными главной страницы. Он берет на себя всю «грязную» работу с сервером и фильтрами, отдавая наружу чистый результат.

• Координирует запросы к API: Запрашивает порции вопросов с сервера (axios.get) на основе текущей страницы и параметров поиска, а также считывает и рассчитывает общее количество страниц пагинации (totalPages).
• Реализует поисковый Debounce: С помощью таймера setTimeout отслеживает ввод букв в инпут и обновляет строку поиска с задержкой в 400 мс. Это защищает бэкенд от лавины холостых запросов на каждый клик по клавиатуре.
• Служит санитаром данных (decodeHtmlString): Пробегается по пришедшему массиву вопросов, срезает технические кавычки бэкенда по краям строк, а через виртуальный тег textarea расшифровывает текстовые мнемоники спецсимволов (&lt; \(\rightarrow \) <, &quot; \(\rightarrow \) ").
• Динамически собирает уникальные теги: На основе пришедших вопросов через структуры new Map() собирает уникальные массивы специализаций и навыков без дубликатов, формируя аккуратные кнопки для сайдбара параметров.
• Проводит глубокую клиентскую фильтрацию: Накладывает на массив вопросов метод .filter(), проверяя контент на одновременное соответствие выбранным специализациям, навыкам, диапазонам сложности и точечному рейтингу.
• Синхронизирует пагинацию: С помощью функций-декораторов автоматически сбрасывает пагинацию на 1-ю страницу при любом новом клике по кнопкам фильтров в сайдбаре, предотвращая пустые экраны. При этом сохраняет чистые нативные методы React для корректной работы стрелок переключения страниц.
