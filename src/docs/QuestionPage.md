Компонент QuestionPage.jsx (Контейнер)
Роль в архитектуре: Управляющий компонент высшего порядка (Smart/Container Component). Отвечает за бизнес-логику, взаимодействие с API, маршрутизацию и координацию данных.

⚙️ Внутренняя логика и состояние:
• id (из useParams): Динамический идентификатор текущего вопроса, извлекаемый из URL (/questions/:id). Служит главным триггером для перезапуска эффектов загрузки. Передает данные в компонент QuestionSlider
• Стейты данных (question, loading, error): Управляют жизненным циклом асинхронного запроса к API. При изменении id стейт loading принудительно сбрасывается в true, предотвращая утечку данных предыдущего вопроса на экран.
• decodeHtmlString(htmlStr): Внутренний хелпер-санитар. Регулярным выражением срезает технические кавычки бэкенда (" или "$), а через виртуальный элемент textarea декодирует экранированные спецсимволы (&lt; → <, &quot; → "), подготавливая чистый HTML для дочерних блоков.

🛡️ Отказоустойчивость и защита от Null (Guard Clause):
Чтобы избежать фатальных ошибок сборки данных (Cannot read properties of null), в теле компонента развернута строгая проверка if (question). Логика динамического сбора уникальных специализаций и навыков через Map запускается только после успешного завершения загрузки.

📐 Каркас разметки (Архитектурный слой):
Компонент формирует общую двухблочную CSS-сетку дашборда с локальным переключением внутренних состояний:

<main className={styles.layoutDashboard}>
  <article className={styles.mainContentLeft}>
    {/* Локальный тернарный оператор загрузки и ошибок */}
    {loading ? <QuestionSkeleton /> : error ? <QuestionError /> : <QuestionContent />}
  </article>

  {/* Component Guard: Parameters рендерится только при наличии объекта question */}
  {question ? (
    <Parameters isDetailPage={true} question={question} />
  ) : (
    <div className={styles.sidebarSkeletonPlaceholder}>Загрузка параметров...</div>
  )}
</main>


Хелпер декодирования и зачистка опасного HTML
• decodeHtmlString — это подготовка данных (чистка и исправление "битых" строк в JavaScript-слое). 
	1. Лишние кавычки: Регулярное выражение htmlStr.replace(/^["']|["']\$/g, '') намертво срезает эти кавычки и знаки $ по краям строки, оставляя только чистый контент.
	2. СпецСимволы: Создает невидимый виртуальный элемент document.createElement('textarea'), кладет туда эту строку и забирает обратно через .value. Браузер автоматически "расшифровывает" спецсимволы, превращая обратно &lt; в <, &gt; в >, а &quot; в ".
• dangerouslySetInnerHTML — это вывод данных на экран (вставка готовой строки в HTML-тег).

Как выглядит их совместный конвейер в вашем коде (Шаг за шагом):
1. Запрос к серверу: Вы делаете axios.get. С сервера прилетает "грязный" кусок:
'"&lt;p&gt;Вопрос про &quot;React&quot;&lt;/p&gt;"'
2. Обработка хелпером (decodeHtmlString): Вы пропускаете текст через функцию.
	• Сначала убираются внешние кавычки: &lt;p&gt;Вопрос про &quot;React&quot;&lt;/p&gt;
	• Затем textarea расшифровывает спецсимволы: <p>Вопрос про "React"</p>
3. Сохранение в стейт: В setQuestion ложится идеальная, чистая HTML-строка.
4. Вывод на экран: Вы передаете эту чистую строку в dangerouslySetInnerHTML. React видит теги <p> и создает правильный абзац, внутри которого написан красивый текст без лишнего технического мусора.
